# Plan: composite-graph error tracing (gh #763) and showing the failed composite type graph (gh #810)

Status: plan only, produced 2026-08-07 (Claude session, reviewed facts verified against the
code base at that date). gh #810 has been closed as a duplicate of gh #763; this plan covers
both. Effort estimate: 2–3 working days in six independently reviewable commits.

## Problem

Host and type graphs can be compound (several enabled graphs composed into one). Errors
detected on the compound object are not traced back to the component(s) that caused them, and
sometimes no single component exists. Selecting such a grammar-level error in the Simulator
fails to highlight anything. Additionally, when the composite type graph has errors,
`CompositeTypeModel.getTypeGraph()` falls back to the implicit type graph and the Preview Type
action is disabled, so the failed composite cannot be inspected at all (the subject of #810).

## Verified ground truth

1. **The CHANGES.md 7.0.7 claim for #810 is wrong.** `release/include/CHANGES.md` claims
   "Resolved gh issues #810, #831, #832" for 7.0.7, but the 7.0.6→7.0.7 commit range contains
   only work on #830–#833; nothing touches `CompositeTypeModel.getTypeGraph()` or
   `PreviewTypeAction`. Likely a typo for #830. The fix should add a corrective changelog note.
2. **Preview Type is disabled on error, deliberately** (commit 87df83282, Nov 2023): the
   constructed type graph would be the implicit one, "which the user can't do anything with
   anyway". #810 asks for the missing better alternative: show the partial composite with its
   errors.
3. **`FormatError.apply` accumulates**: it adds mapped images to the element set while keeping
   the originals, and `AspectJGraph.setSelectionCells` silently skips elements with no cell in
   the shown model. Together: one error can safely carry composite elements *and* all component
   pre-images; whichever tab or preview shows it highlights only what it knows. This is the
   load-bearing mechanic of the whole design.
4. **`FormatErrorSet` projections apply to future adds too**: `FormatErrorSet.add` applies the
   current projection to every added error. Implementation pattern: install `applyInverse(...)`
   chains *first*, then `add(...)` the wrapped errors. `CompositeTypeModel.compute` already uses
   this pattern for the import case; the `TypeGraph.test()` failure branch creates a fresh set
   with no projections — that is the type-side bug.
5. **Cell error decoration (red marking) in tabs comes from the resource model**
   (`AspectJModel.loadViewErrors`), not the grammar; composite-stage errors will never decorate
   component tabs. Only selection highlighting works there; decoration of composite errors
   belongs in the preview dialog.
6. **A type-side fixture exists**: `junit/types/composite.gps` (two individually correct type
   graphs whose combination is ambiguous) with `TypeCheckTest.testComposite`.
7. **`AspectGraph.mergeGraphs` has a second caller** (`transform/Transformer`), so its signature
   must be preserved or wrapped.
8. `graph.Morphism<N,E>` is a `GraphMap` and feeds directly into
   `FormatErrorSet.applyInverse(GraphMap)` — the natural return type for an extended
   `TypeGraph.add`.

Key locations (line numbers as of 2026-08-07): `CompositeHostModel.compute` (the composite-
stage wrap with no resource argument, ~:159-167), `AspectGraph.mergeGraphs` (~:752-850, the
`transfer` morphism is discarded), `CompositeTypeModel.compute` (~:121-175, `test()` failures
wrapped with `this`, ignored by `FormatError.addContext`), `TypeGraph.add` (~:113-152, returns
only a node map; `componentMap`/`Sub` bookkeeping exists), `TypeGraph.test` (~:248-339, some
errors carry no graph at all — the "no single component" case), `Simulator.selectDisplayPart`
(~:453-488), `SimulatorModel.changeSelectedSet` (`retainAll` drops non-resource names).
Attribution precedents: `GrammarModel` settings errors (nested error first, then
`FormatError.resource(KIND, name)`), `CompositeControlModel.getAllPartErrors`.

## Design decision: the "no single component" case

**Component-first attribution with the preview dialogs as the composite view. No dedicated
tab.**

- *Primary route (fixes #763 clicking)*: every composite-stage error is (a) back-mapped so its
  element set contains composite elements plus all component pre-images, and (b) attributed
  with `FormatError.resource(KIND, name)` for **every** contributing component (`FormatError`
  natively supports multiple resource names). `Simulator.selectDisplayPart` then needs no
  structural change; in the genuinely multi-component case the error partially highlights in
  whichever component is selected — the honest answer.
- *Secondary route (fixes #810, completes #763)*: the composite object itself is made viewable
  via the existing `PreviewTypeAction`/`PreviewHostAction` + `GraphPreviewDialog`, extended
  with error decoration.
- *Rejected*: a dedicated read-only composite tab (a tab implies a resource;
  `SimulatorModel.changeSelectedSet`'s `retainAll` and the display/tab lifecycle would all need
  special-casing — high cost, low benefit over the dialog). Also rejected: auto-opening the
  preview dialog on error click as the primary action (intrusive); it is only a fallback for
  errors with no resource attribution (stage 6).

## Stages

### Stage 1 — `TypeGraph.add` returns a full morphism (plumbing)
Change the return type from `Map<TypeNode,TypeNode>` to `Morphism<TypeNode,TypeEdge>` (created
via `new Morphism<>(getFactory())`; fill node and edge maps in the existing copy loops).
Callers: `TypeGraph.clone()` ignores the result; `CompositeTypeModel.compute` replaces its
`nodeMergeMap` with the combined morphism (the `applyInverse(GraphMap)` overload then also
covers edges). Also retain per-component morphisms (`Map<TypeModel,Morphism<...>>`) for
stage 2. No behavioural change; existing tests stay green. ~1h.

### Stage 2 — Attribute composite type-graph errors (#763, type half)
In the `test()` failure branch of `CompositeTypeModel.compute`: create the fresh
`FormatErrorSet`, install projections first (`applyInverse(mergeMap)`, then per component
`applyInverse(model.getMap())` — composite TypeNode/Edge → component TypeNode/Edge → component
AspectNode/Edge), compute contributing components per raw error (intersection of the error's
elements with each per-component morphism's images), and add as
`errors.add("%s in the composite type graph", error, resources)` with
`FormatError.resource(TYPE, qualName)` records — nested error first, resource records last so
they win the `resourceKind` write (settings-error precedent in `GrammarModel`). Do not
drive-by-change `TypeGraph.test()` beyond what attribution needs.
Test: extend `TypeCheckTest.testComposite` — assert resource kind TYPE, resource names contain
both components, and element sets intersect the component sources' aspect elements (the
GUI-independent proxy for "clicking highlights"). ~3h.

### Stage 3 — Retain and show the failed composite type graph (#810)
- `CompositeTypeModel`: new `@Nullable TypeGraph partialTypeGraph` + `getPartialTypeGraph()`,
  reset in `notifyWillRebuild()`, set in `compute()` on all paths (test-failure branch: graph
  is already fixed — store before `errors.throwException()`; earlier failures: `setFixed()`
  whatever was built; success: store the successful graph, so the getter is uniform).
  **Do not change `getTypeGraph()`**: the implicit fallback keeps editors and CLI functional.
- `PreviewTypeAction`: enable iff `typeModel.isMultiple()`; show `getPartialTypeGraph()`. On
  errors, map the model errors onto the preview graph via `GraphConverter.toAspectMap` +
  `FormatErrorSet.transfer`, and show via a decorated `GraphPreviewDialog`.
- `GraphPreviewDialog`: optional `FormatErrorSet` parameter; decorate cells with
  `jCell.getErrors().addError(error, true)` mirroring `AspectJModel.loadViewErrors`
  (including the edge-source fallback).
- Changelog entry under "Upcoming release", noting the erroneous 7.0.7 entry.
Verify manually against `junit/types/composite.gps`. ~3–4h.
Caveat: `setFixed()` on an import-incomplete graph triggers edge-subtype-map construction —
verify no assertion assumes resolved imports; if one does, restrict `partialTypeGraph` to the
test-failure case and document.

### Stage 4 — Retain the merge morphism, attribute composite host errors (#763, host half)
- `AspectGraph`: new record `Merge(AspectGraph graph, AspectGraphMorphism transfer,
  Map<QualName,AspectGraphMorphism> componentMaps)` returned by a new `mergeGraphs` variant;
  the existing signature stays as a delegating wrapper (for `Transformer`). The per-graph
  morphisms are built from data already in hand in the merge loop; zero cost on the
  single-graph path.
- `CompositeHostModel`: store the `Merge` (reset in `notifyWillRebuild`); in the `compute()`
  catch block, install `applyInverse(merge.transfer())` before adding, compute contributing
  components via the component maps, add with `FormatError.resource(HOST, name)` records.
  Single-component case: wrap with `model.getSource()` so attribution works there too
  (currently lost even for one graph).
~3h.

### Stage 5 — Host-side regression fixture + test
New fixture `junit/types/composite-host.gps`: one type graph; two enabled host graphs, each
individually well-typed, sharing an `id`-node whose merge is ill-typed (incompatible node
types — a static typing error, independent of exploration; avoid multiplicity-based errors,
whose check timing is less certain). New JUnit 4 test (`HostMergeTest`): each host model
individually error-free; start-graph model errors non-empty; per error kind HOST, names cover
the causing components, elements intersect each component's source; `getSource()` still
available despite errors (Preview Host keeps working). ~2–3h.

### Stage 6 (optional polish) — GUI routing fallback and host preview decoration
`Simulator.selectDisplayPart`: if no display resolves and the entry is a `FormatError` with a
graph, open `GraphPreviewDialog` on that graph with the error decorated. `PreviewHostAction`:
pass the start-graph model errors to the decorated preview, symmetrical with stage 3. ~2–3h.

## Risks

- **FormatError equality/dedup**: equality includes elements; enriching element sets and
  rewording messages changes identity. Only `TypeCheckTest.testComposite` currently asserts on
  these errors (non-emptiness). Grep for message strings before rewording. Per-component and
  composite errors never coexist in one set (`errors.throwException()` separates the stages).
- **Projection ordering**: projections → attribution computation → add. `applyInverse` after
  `add` would still mutate existing errors, but attribution reads pre-images and must run after
  projections are installed.
- **Null-annotation web**: `CompositeHostModel` is `@NonNullByDefault`, `CompositeTypeModel` is
  not — match each file's existing convention; no drive-by annotation.
- **GUI threading**: all new model state is computed inside `compute()` under the existing lazy
  `synchronise()` regime; dialog decoration stays in action code (EDT).
- **CLI hot path**: extra work is one map insert per element on merge paths and error-branch
  only inversions; the success path of grammar loading is effectively unchanged.
- **`retainAll` silently dropping pseudo-names** (`g1_g2`, composite-type) is relied on as a
  feature; note this in code comments.
